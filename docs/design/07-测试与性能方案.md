# 07 测试与性能方案

## 第一部分：测试方案

### 1. 测试金字塔

```
                 ┌────────────────────────────┐
                 │  E2E / IDE 集成测试          │  少量、关键路径
                 │  (VS Code test-electron /    │
                 │   VS Experimental Instance)  │
                 ├──────────────────────────────┤
                 │  协议与组件测试              │
                 │  DAP 适配器 / VS MEF 组件    │
                 ├──────────────────────────────┤
                 │  语言核心单测                │  大量、快速
                 │  (vitest / xunit)            │
                 ├──────────────────────────────┤
                 │  双引擎一致性测试集            │  跨仓库共享
                 │  (.sb + 期望输出/调试脚本)     │
                 └──────────────────────────────┘
```

### 2. 语言核心单测（复用现有资产）

| 侧 | 框架 | 来源 | 覆盖 |
|---|---|---|---|
| TS | vitest | 拷贝升级 `SmallBasicOnline/tests/compiler`（jasmine 语法平移） | scanner/parser/binder/runtime/services 全套 |
| .NET | xunit 2.9 + FluentAssertions 7 | 拷贝升级 `SmallBasicEditor/Source/SmallBasic.Tests`（netcoreapp2.0 → net8.0，SDK 风格项目） | Scanning/Parsing/Binding/Runtime/Services 全套 |

两侧现成的测试辅助语义等价（`verifyRuntimeResult(text, input, output)` ↔ `VerifyLoggingRuntime`），是移植正确性的第一验证。

### 3. 双引擎一致性测试集（共享资产）

目录：`visual_studio_code_plugin/conformance/`（VS 侧经 `Compile Include` 链接同一目录）。

```
conformance/
├── programs/           # .sb 测试程序（覆盖全部语句/运算符/库调用/事件）
│   ├── statements/  expressions/  libraries/  events/
├── expected/           # 每程序一个期望 transcript（TextWindow I/O 日志 + 终态内存）
└── debug/              # 调试场景脚本 DSL（断点行集合 + 期望停止序列 + 变量快照）
```

执行器（两侧各一个薄 runner）：

- TS：`conformance.runner.ts` — 逐程序 `new Compilation` → `ExecutionEngine` + 假 I/O → 实际 transcript 与 expected 比对。
- .NET：`SB.Conformance.Tests` — 同一批 `.sb` 走 `SmallBasicEngine` + `LoggingTestLibraries` 模式 → 比对。

**transcript 格式**（沿用两个仓库已有的日志形态）：

```
> WriteLine "Hello"
< ReadNumber            # 输入事件，注入值 42
> WriteLine 84
Terminated
```

CI 门禁：任何一侧 PR 必须通过两侧全套一致性测试 → 双引擎行为不发散。

### 4. DAP 适配器协议测试

用 DAP 客户端测试工具（TS 侧 `vscode-debugadapter-testsupport`；.NET 侧自研 50 行 DAP 客户端 harness）驱动适配器进程：

| 用例组 | 断言 |
|---|---|
| setBreakpoints | 可执行行 verified=true；空行/注释行吸附与 verified 语义 |
| launch→breakpoint | 命中行号、reason、thread id |
| next/stepIn/stepOut | 停止行序列与栈深变化符合 §05 语义表 |
| stackTrace/variables | 帧名、行号、变量值与数组递归展开 |
| pause | 死循环程序可暂停且停在合法行 |
| exception/terminate | 运行时错误上报与退出码 |
| 输入阻塞 | `Read` 期间继续请求不推进，注入输入后恢复 |

调试 DSL（`conformance/debug/*.dbg`）示例：

```
break 3, 7
run           -> stop at 3 (breakpoint)
next          -> stop at 4 (step)
stepInto      -> stop at 7 (breakpoint)   # 子程序内
vars          -> x = 42
continue      -> terminated
```

两侧适配器各自解析执行同一 DSL，比对停止序列与变量快照。

### 5. IDE 集成测试

| 侧 | 手段 | 关键用例 |
|---|---|---|
| VS Code | `@vscode/test-electron` | 激活；打开 `.sb` → 诊断出现；补全列表含 `TextWindow`；TextMate scope 快照（`vscode-tmgrammar-snap`）；`smallbasic.run` 终端输出 Hello；F5 调试断点命中 |
| VS | MEF 组合单测（`SB.Editor.UnitTests`：`IClassifier`/`IAsyncCompletionSource` 直接组合调用）+ Experimental Instance 冒烟（CI 可选） | 分类 span 快照；补全项；ErrorTagger span；模板命令创建文件 |

**TextMate/分类器着色测试**：同一批 `.sb` 片段两侧各自做"token→分类"快照比对，分类集合（keyword/string/number/comment/library/subroutine/label）两端语义一致。

### 6. 测试门禁（CI）

```
PR 触发:
  1. lint + typecheck（两侧）
  2. TS 核心 vitest（含一致性 runner）
  3. .NET 核心 xunit（含一致性 runner）
  4. DAP 协议测试（两侧）
  5. VS Code 集成测试（Linux + Windows）
  6. 打包（vsix / VSIX）冒烟
主分支追加: VS Experimental Instance 冒烟（Windows agent）
```

## 第二部分：性能方案

### 1. 性能预算

| 指标 | 预算 | 依据 |
|---|---|---|
| 全量编译（1k 行典型教学程序） | < 5 ms | 在线版每次击键全量编译已验证可行 |
| 全量编译（10k 行极端） | < 50 ms | 超出则防抖内一次，用户无感 |
| 补全响应（缓存命中） | < 30 ms | VS/VS Code 补全体感阈值 ~100ms |
| 诊断刷新延迟 | ≤ 300 ms（防抖 150 + 编译 + 渲染） | |
| 着色重分类（VS）/语义令牌（VS Code） | < 16 ms/帧级 | 不阻塞键入 |
| 调试逐行推进开销 | < 1 ms/行（判定） | 适配器循环 O(1) |
| 扩展激活 | < 200 ms（懒激活 onLanguage） | |
| 包体积 | VS Code vsix < 1.5MB；VSIX < 80MB（含自包含运行时） | |

### 2. 性能手段清单

**语言核心**：
- 编译缓存以 `(uri, version)` / `(ITextBuffer, ITextVersion)` 为键，四个语言功能共享一份 `Compilation`。
- 诊断防抖 150ms；补全/悬停走同步缓存路径。
- 引擎为同步全量编译——不引入增量解析复杂度（SB 程序规模不需要）。

**VS Code 侧**：
- 懒激活（`onLanguage:smallbasic`）；esbuild 单文件打包消除模块加载开销。
- 运行/调试在独立 Node 子进程，扩展宿主永不阻塞。
- 调试循环 `setImmediate` 分段（每段 ≤5ms），保证 pause 请求即时响应。
- >5 万行极端文件：二期迁 web worker（接口已按纯数据设计，迁移零 API 变化）。

**VS 侧**：
- 解析/绑定在后台线程，结果经 `Task` 投递 UI 线程；`IAsyncCompletionSource` 全程异步。
- 分类器按可见区域增量请求（VS 自行分片调 `GetClassificationSpans`），实现上仍全量扫描但仅返回请求区间 span。
- `SBCompilationService` 在缓冲关闭时主动释放。

**测量保障**：
- 核心编译基准：`benchmarks/`（TS vitest bench / .NET BenchmarkDotNet 轻量配置），固定 1k/10k 行样例，CI 记录趋势，回归 >20% 报警。
- 集成测试中埋点：补全耗时、诊断延迟、调试行推进速率，输出为测试产物。
