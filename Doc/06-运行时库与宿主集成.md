# 06 运行时库与宿主集成

Small Basic 的 20 个标准库对象（Array, Clock, Controls, Desktop, Dictionary, File, Flickr, GraphicsWindow, ImageList, Math, Mouse, Network, Program, Shapes, Sound, Stack, Text, TextWindow, Timer, Turtle）在两个引擎中都是**接口注入**模式：

- .NET：`IEngineLibraries` 聚合 20 个接口（`Libraries.Generated.cs` 生成），宿主提供实现类。
- TS：`RuntimeLibraries` 中各库持有插件接口（如 `ITextWindowLibraryPlugin`），宿主注入实现。

这决定了插件的主要工作量在**宿主 I/O 落地**，而非编译器改造。

## 1. 库分期与矩阵

| 库 | 性质 | VS Code（TS 引擎） | VS 2026（.NET 引擎） | 分期 |
|---|---|---|---|---|
| TextWindow | 控制台 I/O | 集成终端（Pseudoterminal） | SB.RunHost 控制台 / 调试时命名管道桥 | **MVP** |
| Math, Text, Array, Stack, Dictionary, Clock, Program, Timer | 纯计算/无 UI | TS 版已有实现（直接保留） | 对照 TS 版实现（无 I/O，工作小） | **MVP** |
| File | 文件读写 | Node `fs`，沙箱限制于工作区 | `System.IO`，用户目录 | M2（安全策略见 §4） |
| GraphicsWindow, Shapes, Turtle, Mouse, Controls, ImageList, Sound | 图形/交互 | Webview 面板 + Canvas（参考 SmallBasicOnline 的 Konva 实现） | WPF 窗口 + Canvas | M3 |
| Flickr, Network, Desktop | 网络/系统 | 默认禁用，设置项开启 | 同左 | M4（可选） |

**探测**：编译期 `RuntimeAnalysis`/`compilation.kind` 已知程序用到哪些库 → 运行时按需提示（如"该程序使用 GraphicsWindow，将在图形窗口中运行"或"MVP 暂不支持"）。

## 2. VS Code 侧实现

### 2.1 TextWindow → 集成终端

```ts
// run/text-window-terminal.ts
class TerminalTextWindow implements ITextWindowLibraryPlugin {
  private inputBuffer: BaseValue[] = [];
  constructor(private pty: vscode.Pseudoterminal, private engine: ExecutionEngine) {}
  writeText(value: string, appendNewLine: boolean) { /* pty 写 + 颜色码 */ }
  inputIsNeeded(kind: ValueKind)                   { /* 置等待输入态，回显提示 */ }
  checkInputBuffer(): BaseValue | undefined        { /* 行缓冲弹出；Read/ReadNumber 解锁 */ }
  get/setForegroundColor / get/setBackgroundColor  { /* ANSI 256 色映射 TextWindowColor */ }
}
```

- 颜色：SB 的 16 色枚举 → ANSI escape；`Clear()` → 终端清屏序列。
- `Read()`/`ReadNumber()` 阻塞语义与 DAP 适配器的 `BlockedOnInput` 处理衔接（见 05 §2）。

### 2.2 GraphicsWindow → Webview（M3）

- `vscode.window.createWebviewPanel`，内嵌 canvas 页面；宿主侧把 `DrawLine/FillRectangle/...` 序列化为消息 post 到 webview 渲染。
- 渲染参考 `SmallBasicOnline/src/app` 的 Konva 场景组织（图层/形状句柄表），但改用原生 Canvas 2D 以去依赖。
- 事件（`MouseDown/KeyDown`）：webview → 宿主消息 → `LibraryEventInstance.raise(engine)`。
- 与终端并存：`compilation.kind` 决定开终端、开图形面板还是两者。

## 3. VS 侧实现

### 3.1 `SB.RunHost`（控制台宿主）

`ConsoleLibraries : IEngineLibraries` 聚合 20 个实现类：

| 库实现 | 要点 |
|---|---|
| `ConsoleTextWindowLibrary` | `WriteLine`→`Console.Out`；`Read/ReadNumber`→阻塞 `Console.ReadLine` + `engine.InputReceived()`；颜色→`Console.ForegroundColor`（16 色一一对应） |
| `MathLibrary` 等纯计算 | 直接对照 TS 版语义实现；`Clock` 用本地时区；`Program.Delay`→`Task.Delay`；`Timer`→`System.Threading.Timer` 触发 `RaiseEvent` |
| `FileLibrary` | `System.IO`，M2 落地，默认根=用户 `Documents\SmallBasic`（可配） |

调试模式下 `TextWindow` 不走进程控制台（stdin/stdout 被 DAP 占用），改走命名管道与终端代理进程通信（见 05 §4）。

### 3.2 GraphicsWindow → WPF 窗口（M3）

- `SB.RunHost` 增加 `--graphics` 模式：进程内建 WPF `Window` + `Canvas`，STA 线程消息循环与引擎异步循环通过 `SynchronizationContext` 桥接。
- `Shapes` 维护形状句柄表（Add/Move/Rotate/Zoom/Remove/Animate）；`Turtle` 在 Canvas 上以折线累积绘制；`Sound/ImageList` 用 WPF MediaPlayer/Image 控件。
- 事件（Mouse/Key/Controls）→ `SmallBasicEngine` 事件回调压栈机制（引擎原生支持事件子模块帧）。

## 4. 安全策略

| 能力 | 默认 | 配置项 |
|---|---|---|
| File 读写根目录 | VS Code：工作区；VS：`Documents\SmallBasic` | `smallbasic.file.rootPath` |
| Network/Flickr | 禁用 | `smallbasic.enableNetwork`（明示开关） |
| Desktop（打开 Shell） | 禁用 | 不支持计划 |
| 调试/运行进程 | 独立子进程，可随时终止；CPU 看门狗（可选，默认关） | `smallbasic.run.watchdogSec` |

## 5. 库文档数据流（两端共享）

```
HomeSite SmallBasicLibrary.xml (22语言)
   └─ scripts/generate-library-docs ─→ library-docs.json
        { object: { description, methods: { name: { signature, summary, params[], returns } },
                    properties: {...}, events: {...} }, keywords: {...} }
        ├─ VS Code: 补全 detail/documentation、hover markdown、signature help
        └─ VS:      补全 Description、QuickInfo、Signature Help
```

生成逻辑参考 `SmallBasicHomeSite/src/app/documentation/documentation.service.ts`（签名形如 `GraphicsWindow.DrawLine(x1, y1, x2, y2)`，过滤 `Internal.*` 内部类型）。

**对账**：构建期校验 JSON 与两套编译器内置元数据（TS `LibrariesMetadata` / .NET `Libraries.Types`）的成员清单一致，缺失即构建告警——防止"文档有而引擎无"或反之。

## 6. 验收要点

- MVP：`TextWindow.WriteLine/Write/Read/ReadNumber/Clear` + 颜色 + 8 个纯计算库在两端跑通一致性测试集。
- 事件库（Timer/GraphicsWindow 事件）须有专门的一致性用例（事件帧压栈顺序）。
- 所有宿主 I/O 实现必须可注入假实现（沿用 `TextWindowTestBuffer` 模式），保证库逻辑可脱离 IDE 单测。
